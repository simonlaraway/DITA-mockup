Pagination and rate limits

List endpoints return results in pages, and each API key can make a limited number of requests per minute.

Pagination

List endpoints accept a limit (1–100, default 25) and return a next_cursor. To get the next page, pass it back as cursor. When next_cursor is null, you've reached the end.

Cursors are stable: records added while you page through a list don't cause duplicates or gaps.

Rate limits

Each key can make 600 requests per minute. Every response includes these headers:

HeaderMeaning
X-RateLimit-LimitRequests allowed per minute
X-RateLimit-RemainingRequests left in the current window
X-RateLimit-ResetUnix time when the window resets

If you exceed the limit, you get a 429 response with a Retry-After header. Wait that many seconds before retrying, and use exponential backoff for repeated failures.
